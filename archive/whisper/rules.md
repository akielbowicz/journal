## CI Release Pipeline Gotchas (charly-vibes suite)

### `--locked` breaks with newer CI Rust
CI runs Rust 0.98.0 (or whatever latest stable is), which expects a different Cargo.lock format than local 1.93.x.
**Fix:** Remove `--locked` from build steps in release.yml. Keep it in CI.yml (no cross-compile there).

### `cargo publish` dirty directory
Cargo.lock gets regenerated by CI's different Rust version. `cargo publish` checks working dir is clean.
**Fix:** Add `--allow-dirty` to `cargo publish` step AND add `include` field to Cargo.toml to control what gets packaged.

### `include` field required
Without `include`, `cargo publish` packages everything in the repo (beads, openspec, .wai, etc.). Wai was packaging 998 files / 68MiB.
**Fix:** Add `include = ["src/**/*", "/build.rs", "/Cargo.toml", "/Cargo.lock", "/LICENSE", "/README.md"]` to Cargo.toml.
**Note:** If the crate has a `build.rs`, it MUST be in the include list.

### Binary names vs crate names
Espectacular's Cargo.toml has `[[bin]] name = "ah"` (not `espectacular`). The release.yml was trying to copy a non-existent `espectacular` binary.
**Fix:** Only copy actual binary names from `target/release/`.

### Homebrew/Scoop tap updates
The release workflow's homebrew/scoop update steps fail if `TAP_GITHUB_TOKEN` secret isn't set. This is non-critical — the GitHub release and crates.io publish are the important parts.
### pi install/update does not re-sync flat-skills directories
`pi install` and `pi update` only update the npm package in `.pi/agent/npm/node_modules/`. They do NOT re-copy skills to flat-install locations (`~/.agents/skills/`, `~/.config/agents/skills/`). Any npm package that provides skills via both pi's pi-package/skills/ AND a flat-install path MUST handle re-sync in its own postinstall script. For incitaciones, `scripts/generate-pi-resources.mjs` includes `reSyncFlatInstallSkills()` for this purpose.

### mise built-in plugins can override custom `mise.toml` config
If `mise.toml` has a custom backend tool entry with URL templates (e.g. Julia with `url = """..."""`), mise may ignore the custom template and use its own built-in plugin's URL resolution. This can produce wrong download URLs (e.g. `1.11.9/` instead of `1.11/`).
**Fix:** Remove the tool entry from `mise.toml` and install it via an alternative mechanism (e.g. GitHub Actions' `setup-julia`, `setup-dotnet`, etc.).

## Beads (`bd`) batch issue creation — workflow gotchas

### `bd create -f <file>` is the batch path; `--stdin` ignores some flags
`bd create -f file.md` parses `## Issue Title` sections and is the reliable batch path. The `--stdin` / `--body-file -` alias reads the description from stdin but **does** honor `-t`/`-p`/`-l`/`--silent` flags — useful when a Python driver sets metadata per-ticket.

### `bd list` defaults to 50 open issues — use `--all --limit 0` for full set
`bd list --json` silently caps at 50 open issues. To enumerate every issue (including closed, or beyond 50) for metadata analysis: `bd list --all --limit 0 --json`.

### Markdown batch format: `**Field:**` not `**Field**:`
In `bd create -f`, frontmatter (`---` block) sets type/priority/labels. The `**File:**` / `**Files:**` label convention puts the colon **inside** the bold markers (`**File:**`), not after (`**File**:`). Regex for parsing must match `\*\*Files?:\*\*`.

### Severity labels can silently drop on P3 (LOW) issues
Creating 14 `dont` issues with `-l severity:low,...`: the 5 LOW-severity (P3) issues lost their `severity:low` label while the other 9 kept theirs. Label propagation has a quirk at P3. **Mitigation:** after batch creation, verify labels with `bd list --json | jq` and re-add any dropped: `bd label add <id> severity:low`.

### `metadata.files` must be set explicitly — body text doesn't count
`bd create` does not parse file paths from the description body into structured metadata. For file-based queries (`bd list --file`) and shared-file analysis to work, set `metadata.files` after creation: `bd update <id> --metadata '{"files":["src/main.rs"]}'` (JSON object form, not `--set-metadata 'files=["..."]'` which stores as a string).

### `bd close` needs no flag; `--note` isn't a close flag
`bd close <id>` closes with status `closed`. To record a reason, use `--reason <text>` or add a `bd comment <id> <text>` separately. `--note` is not a close-flag.

### `bd dolt push` requires a configured remote
`bd dolt push` fails with "Supported remote URLs..." if no remote is set. Add one per repo: `bd dolt remote add origin git+ssh://git@<host>/<org>/<repo>.git`. Push can fail with divergent-history on repos that had independent `bd init` — use `bd bootstrap` to clone instead in that case.

### `bd create --description` with backticks breaks shell interpolation
Backticks in an inline `--description="..."` trigger shell command substitution and silently corrupt/abort the ticket. **Use `--body-file <path>`** (or `--stdin`) to pass descriptions containing code, paths, or backticks. Environment-variable expansion (`$VAR`) in inline descriptions is also unsafe.

### Re-triggering a tag-pushed publish workflow after a CI fix
If a tag-triggered GHA publish workflow (e.g. `on: push tags`) fails because of a CI config bug, fixing the workflow on `main` does NOT fix the failed run — the workflow checks out the tag ref, not the branch. The tag must be moved to the fixed commit and re-pushed:
```bash
git tag -d v0.6.0
git push origin :refs/tags/v0.6.0
git tag v0.6.0
git push origin v0.6.0
```
This re-triggers the publish workflow against the fixed tree.

### WeasyPrint `RecursionError` on truncated email HTML — use DOM-level truncation
Email HTML (Mailchimp/Drip templates) is deeply nested tables; truncating by regex and hand-appending guessed closing tags (`</td></tr></table></div>`) leaves unbalanced nesting that crashes WeasyPrint with `RecursionError` in cffi. Instead parse with BeautifulSoup and truncate structurally: find the signature text node, then for each ancestor up to the document root `extract()` all `next_sibling`s. Always verify post-cut text is free of boilerplate markers before rendering.

`openspec validate --strict` gotchas (all hit this session):
- Requirement headers must be exactly `### Requirement: ...` — a `[TAG]` prefix before "Requirement:" is not parsed (project convention puts traceability tags in headers; base specs pass only because each section also has untagged requirements).
- SHALL/MUST is checked against the **first physical line of the requirement body only** — a keyword on a wrapped continuation line fails; also new requirements split out of an existing one need their own first-line SHALL.
- Two pending changes MODIFIED-ing the same requirement with full-text rewrites collide silently (second apply erases the first's addition). Fix pattern: declare an application order, rebase the later delta onto the earlier change's output text, and document it in both proposals.
- A delta requirement can target the wrong capability file (backend's pipeline delta carried dataframe's `explain()` requirement) — validator passes; catch it by cross-checking requirement names against base specs (`grep -h '^### Requirement:' .../specs/*/spec.md | sort | uniq -d` after filtering expected base+delta pairs).

# incitaciones — operational knowledge

## Build & release
- Distilled skills live in `content/distilled/`; pi-package is generated by `scripts/generate-pi-resources.mjs` (runs on prepare/postinstall/prepack)
- Publish: `npm version patch|minor|major` → push commit + tag (`v*`) → CI runs npm publish
- Install: `pi install npm:incitaciones` or `npx incitaciones install`

## Flat-skill re-sync
- `generate-pi-resources.mjs` includes `reSyncFlatInstallSkills()` that runs after pi-package generation
- Scans `~/.agents/skills/`, `~/.config/agents/skills/`, `.agents/skills/` for incitaciones markers
- Re-syncs them with current distilled content + npm:VERSION stamp
- This is needed because pi install/update does NOT re-copy flat skills

## Skills
- Three documentation skills use progressive-disclosure format: SKILL.md + references/ dir
- research-documentation, implement-documentation, review-documentation
- Each triggers reference file loading at specific stages via the SKILL.md procedure
- The canonical theory source is `content/research-documentation-frameworks.md`; operational depth is in `content/research-finding-library-docs-best-practices.md`

## Publish workflow gotchas (learned 2026-07-31, v0.4.0 release)
- **`npm version` refuses on a dirty working tree** — even if *your* changes are committed, pre-existing uncommitted work from other sessions (README overhauls, stray `.beads/` changes, untracked dirs) blocks it. **Workaround:** bump `package.json` manually, `git commit -m "X.Y.Z"`, `git tag -a vX.Y.Z -m "X.Y.Z"`, push. Identical net result.
- **`git pull --rebase` can prune a just-created local tag** if the remote has a deletion for that tag ref — it fetched `[deleted] (none) -> v0.4.0` and removed my local tag before I pushed it. **Recover:** `git tag -a vX.Y.Z -m "…" <commit-sha>` to recreate at the version commit, then push the tag. Always verify with `git rev-parse vX.Y.Z` after pull. Recurred on v0.6.0 (2026-09-01) where the tag vanished after `git pull --rebase` with NO remote deletion ever pushed — treat `npm version`'s tag as fragile across any pull; re-check `git tag -l` immediately before `git push origin vX.Y.Z`.
- **`prepack` regenerates `pi-package/`** from the manifest, so new skills ship automatically once committed — no need to stage `pi-package/` manually (it's build output; `git checkout -- pi-package/` to clean after a local dry-run).
- **`just validate` requires `related:` entries to resolve under `content/`** — source research files at repo root with spaces/parens in names break it. Move them to `content/research-*.md` with proper slugs + frontmatter envelope (`source: original` for original research, `source: research-*.md` for derived prompts).

## Progressive-disclosure skill conventions (diagnostician pattern)
- Structure: `content/distilled/<name>/SKILL.md` + `references/*.md`
- SKILL.md is lean: Setup → Procedure (each step says "Read `references/X.md`") → Rules → Source. ~70–120 lines.
- Each reference is a layer/rubric with an **AUDIT checks** subsection (checkboxes) and, for establish-style skills, an **ESTABLISH** subsection with day-by-day artifact tasks.
- Manifest entry: `skill_format: "progressive-disclosure"`, full `eval` block (success/failure signals, stages, references with aliases + `optional` flag). Optional references (e.g. `examples.md`) follow the rule-of-5-universal precedent.
- A **source prompt** `content/prompt-task-<name>.md` with frontmatter (`source: research-*.md`, `related:` cross-links) accompanies the skill; the skill's `## Procedure` mirrors it for isolation readers.
- `just validate-distilled` checks SKILL.md for instruction keywords (step|task|process|your|analyze|create|review|focus|output) and rejects nested 4-backtick code blocks.
- `just sync-manifest` validates all `distilled`/`source` paths resolve and bumps `version` date on content change.

## Rule of 5 review skill
- `/skill:rule-of-5-universal` runs 5-stage review (DRAFT → CORRECTNESS → CLARITY → EDGE CASES → EXCELLENCE) with convergence checks after stages 2–4. Output format in `references/templates.md`; convergence rules in `references/criteria.md`.
- Convergence = no new CRITICAL + new-issue rate <10% vs previous stage + false-positive rate <20%. Can stop before stage 5 if converged.
- Useful for reviewing both prose (research docs) and skill structures.
